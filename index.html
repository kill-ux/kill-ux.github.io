Selected work

Six builds · 2024–2026

01Buy-01

Spring BootAngularMongoDBMinIOEureka
What
E-commerce platform on a microservices architecture (gateway, discovery, user, product, media). I own the Product and Media services.
Decision
JWT is validated once, at the gateway. Services trust the identity headers it forwards instead of re-checking tokens. Product and Media talk over plain HTTP through Eureka with Spring HTTP interface clients, with no Kafka or gRPC where a simple call is enough.
Result
Product Service is built and working. Media Service stores images in S3-compatible object storage (MinIO) and checks product ownership on upload. Product fetches image URLs from Media in one batch request per list instead of duplicating them in its own database.

02Code-Keeper

GitLab CIAnsibleTerraformTerragruntDocker
What
Full CI/CD for a microservices app, with GitLab and runners deployed by an Ansible playbook and staging and production environments provisioned by Terraform on top of my AWS infrastructure project.
Decision
Each service has its own repo and pipeline, and infrastructure lives in a separate infra repo (Terragrunt + Terraform), so app changes and infra changes ship independently. Docker image scanning runs in every pipeline.
Result
Three app pipelines running CI (build, test, scan, containerize) and CD (deploy to staging, manual approval, deploy to production), plus one infra repo managing both environments.

03Cloud Design

AWSECSTerraformPostgreSQL
What
Microservices infrastructure on AWS ECS, fully described in Terraform: API gateway, inventory and billing apps, RabbitMQ, and two PostgreSQL databases.
Decision
ECS on an EC2 Auto Scaling Group capacity provider so the self-hosted databases keep data on persistent EBS volumes. Images are pulled from ECR through VPC endpoints instead of a NAT Gateway to cut cost.
Result
Modular Terraform (VPC, security groups, ALB, ECS, S3 remote state) that rebuilds the whole environment from a single apply.

04Let's Play API

Spring BootMongoDBRedisJWT
What
REST CRUD API for users and products with JWT auth and role-based access: admins manage everything, regular users manage only their own products.
Decision
Stateless JWTs plus a Redis blocklist, so deleting a user or changing a role or password invalidates their tokens immediately instead of at natural expiry.
Result
Full Postman regression suite passing, BCrypt password hashing, global exception handling, and all secrets kept in environment variables.

05Kernel from scratch

NASMx86RustQEMU
What
A Linux-like kernel built in stages: a NASM bootloader in real mode, a second stage, then the switch to 32-bit protected mode (GDT, A20, CR0).
Decision
Start from bare metal so nothing hides behind a library, then write the kernel itself in no_std Rust with a custom target and linker script.
Result
The full chain boots under QEMU: boot sector, stage 2, protected mode, then the Rust kernel writing to VGA memory.

06Orchestrator

Kubernetesk3sDockerRabbitMQPostgreSQL
What
A k3s cluster running a microservices app (API gateway, billing, inventory, RabbitMQ, two PostgreSQL databases) with every component deployed and managed through Kubernetes manifests.
Decision
I used k3s for a lightweight real cluster, and moved from Docker Compose to Kubernetes primitives: Deployments, Services, StatefulSets for the databases, and secrets and volumes for configuration and persistence. Only the gateway is exposed externally.
Result
The whole stack comes up from manifests, and the control plane reschedules failed pods automatically.
